# Campus T28 — fork de ClassroomIO

Este repositorio es un **fork de [ClassroomIO](https://github.com/classroomio/classroomio)**
con las modificaciones que usa el campus de formación de **Think28**
([campus.t28.io](https://campus.t28.io)).

**Base: `v1.0.0`** de upstream, no su `main`. Es deliberado: el campus en
producción corre imágenes derivadas de `classroomio/*:1.0.0`, y basar el fork en
el mismo tag hace que nuestras modificaciones sean el **único** delta. Si se
partiera de `main` —181 commits más adelante en el momento de crear el fork—,
cualquier problema al desplegar tendría dos causas posibles a la vez.

## Por qué es público

ClassroomIO está bajo **AGPL-3.0**. Correr una versión modificada como servicio
de red obliga a ofrecer el código fuente a quien la usa. Este repositorio *es*
esa oferta. No es una decisión de marketing: es la licencia.

Lo que **no** está acá, y nunca va a estar: las credenciales del despliegue (el
`.env` vive solo en el servidor), el material pedagógico y comercial del
producto, y los datos de cualquier cliente.

## Qué se modifica, y por qué

El campus se dicta en **español rioplatense** para empleados de empresas
argentinas, con la marca T28 en lugar de la de ClassroomIO, y necesita algunos
módulos propios del método de formación que upstream no tiene.

Hasta ahora todo eso se aplicaba **parcheando el bundle ya compilado** de las
imágenes oficiales, porque no había dónde construir desde el fuente. Este fork
existe para dejar de hacerlo: los cambios pasan a ser código legible y
revisable, y los parches se van borrando de a uno a medida que su reemplazo
queda verificado en el campus.

## Cómo se construye

`.github/workflows/build-images.yml` construye las tres imágenes
(`dashboard`, `api`, `jobs`) y las publica en GHCR bajo
`ghcr.io/javierledesma28/t28-classroomio/*`. El servidor las consume pinneando
el tag `sha-<7>`; no hay `latest` a propósito.

El workflow **no despliega**. Un push a `main` no puede recrear el campus de un
cliente sin que nadie lo haya pedido.

## Sincronizar con upstream

```bash
git fetch upstream
git merge v1.0.1        # o el tag de la release que corresponda
```
